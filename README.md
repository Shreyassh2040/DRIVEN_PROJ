# CivicFlow — Smart City Assistance and Discovery Platform

CivicFlow is a full-stack civic platform for discovering city services, reporting public infrastructure problems, tracking their resolution, and participating in community decisions. It ships with three connected experiences:

- **Citizen portal** — discover services, report issues, follow updates, vote in polls, manage a profile.
- **Officer console** — triage the complaint queue, assign work, update statuses, add public or internal notes, review performance.
- **Administration console** — oversee complaints, accounts, officers, the service catalogue, community polls, analytics, audit activity and platform settings.

The interface is a premium, responsive SaaS-style design built with HTML5, CSS3 and dependency-free vanilla JavaScript. There is no frontend build step.

## Technology

| Layer | Implementation |
| --- | --- |
| Frontend | HTML5, CSS3 custom properties, vanilla JavaScript (classic scripts, no bundler) |
| Backend | Node.js 18.18+, Express 4 REST API |
| Database | MySQL 8+ (`mysql2` connection pool, parameterised SQL) |
| Authentication | bcryptjs password hashing, JWT bearer sessions |
| Uploads | Multer with MIME verification, size limits and protected photo delivery |
| Maps | Google Maps Platform (optional); honest coordinate and directions fallback when no key is configured |
| Security | Helmet, CORS allow-list, rate limiting, backend RBAC, validation, audit logging |
| Charts | Custom accessible SVG charts (no chart CDN or paid service) |

## Quick start

### 1. Create the database

For a **fresh installation**:

```bash
mysql -u root -p -e "CREATE DATABASE smart_city CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -u root -p smart_city < database/schema.sql
```

For an **existing CivicFlow database**, take a backup first and apply the additive migration instead:

```bash
mysqldump -u root -p smart_city > smart_city_backup.sql
mysql -u root -p smart_city < database/migrations/2026-11-01-platform-upgrade.sql
```

The migration preserves existing users, complaints, tracking IDs and legacy service rows. It is idempotent and can be re-run safely.

> MySQL on macOS with Homebrew commonly uses an empty root password:
> `mysql -u root smart_city < database/schema.sql`.

### 2. Configure the backend

```bash
cd backend
cp .env.example .env
```

Edit `backend/.env` and set at least:

```dotenv
DB_NAME=smart_city
DB_USER=root
DB_PASSWORD=your-mysql-password
JWT_SECRET=replace-with-at-least-32-random-characters
```

Generate a strong JWT secret:

```bash
openssl rand -hex 32
```

### 3. Install and run

```bash
cd backend
npm install
npm start
```

Open **http://localhost:3000**. Express serves both the API and the frontend.

For development with automatic restarts:

```bash
npm run dev
```

### 4. Create your first account

1. Create an administrator with the provisioning command below.
2. Sign in as the administrator and provision officer accounts from **Administration → Officers**.
3. Citizens can register publicly from `register.html`.

## Creating the first administrator

Public registration can never create officer or administrator accounts. Administrators are provisioned only from the backend:

```bash
cd backend
ADMIN_PASSWORD='choose-a-strong-password' npm run create-admin -- \
  --email admin@city.gov \
  --name "City Administrator"
```

Useful options:

```bash
# Promote an existing account to administrator
ADMIN_PASSWORD='...' npm run create-admin -- --email person@city.gov --promote

# Reset an existing administrator password
ADMIN_PASSWORD='...' npm run create-admin -- --email admin@city.gov --reset-password
```

The password must be at least 8 characters. Prefer `ADMIN_PASSWORD` over `--password` so the value does not remain in shell history.

## Environment variables

| Variable | Required | Description |
| --- | --- | --- |
| `PORT` | No | API/frontend port, default `3000` |
| `NODE_ENV` | No | `development` or `production` |
| `DB_HOST` | No | MySQL host, default `localhost` |
| `DB_PORT` | No | MySQL port, default `3306` |
| `DB_USER` | No | MySQL user, default `root` |
| `DB_PASSWORD` | Yes in practice | MySQL password, default empty |
| `DB_NAME` | No | Database name, default `smart_city` |
| `JWT_SECRET` | **Yes** | At least 32 characters. Server refuses to start without it |
| `JWT_EXPIRES_IN` | No | Token lifetime, default `8h` |
| `CLIENT_ORIGIN` | No | Comma-separated allowed browser origins when frontend and API are served separately |
| `GOOGLE_MAPS_API_KEY` | No | Browser key for Maps JavaScript API and Geocoding API |
| `MAX_UPLOAD_MB` | No | Complaint photo limit, default `5` |

`.env` is ignored by git. Never commit real credentials or map keys.

### Google Maps behaviour

- **No key:** service and complaint locations show recorded coordinates, the address and a directions link. No placeholder or fake map is displayed.
- **Key configured:** the public `/api/config` endpoint exposes the browser key and the UI renders interactive maps.

Restrict the key by HTTP referrer and enable only the APIs you use. See [DEPLOYMENT.md](docs/DEPLOYMENT.md) for details.

## Security and data integrity

- Passwords are hashed with **bcryptjs**; hashes are never returned by the API.
- JWTs are verified on every protected request and the account is re-read from MySQL, so deactivation and role changes take effect immediately.
- Public registration ignores any `role` supplied by the client.
- SQL uses parameterised queries throughout.
- Helmet sets a Content Security Policy; CORS uses an explicit allow-list.
- Rate limits: authentication `30 / 15 min`, complaint creation `25 / 15 min`, votes `30 / 5 min`, global API `1200 / 15 min`.
- Uploads are limited by size and verified as images; photos are served only through an authenticated endpoint (`GET /api/issues/:id/photo`).
- Audit records are written for authentication, complaint, assignment, status, account, service, poll and settings actions.
- One vote per citizen per poll is enforced by a database unique key and controller checks.
- Poll options cannot be changed after votes exist; polls with votes cannot be deleted.
- Service categories are referenced by slug; inactive categories and services disappear from the public directory without deleting historical records.
- At least one active administrator must remain.

### Honest data policy

The application does not invent production data. Homepage statistics, complaint counts, service listings, poll results and analytics are read from MySQL. When there is no data, the interface shows an explicit empty state rather than fabricated examples. The only seeded records are the service-category taxonomy and platform settings defaults; no fake users, complaints or services are inserted.

## Running without paid services

**Everything required by this project is free and open source.** You can run the complete platform locally at no cost: Node.js, Express, MySQL, bcryptjs, JWT, Helmet and the vanilla frontend are all free.

The only optional paid dependency is **Google Maps Platform**:

- Leave `GOOGLE_MAPS_API_KEY` empty to use the free fallback (coordinates, address and directions link).
- If you enable Google Maps, Google requires a Cloud billing account. It includes a monthly free usage allowance, but the exact allowance and pricing can change. Check the current [Google Maps Platform pricing](https://mapsplatform.google.com/pricing/) before enabling it.
- The app never calls Google Maps unless a key is configured.

For a public URL, choose a host that supports a long-running Node process and MySQL. Free tiers change frequently; verify current limits before deploying. See [DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Testing

The automated suite runs against a **separate disposable database** (`smart_city_test`) so real data is never touched:

```bash
cd backend
npm test
```

The suite rebuilds the schema, exercises authentication, RBAC, complaints, assignments, status transitions, notifications, polls, services, analytics, settings, CSV export and input validation, then drops the test database.

Keep the test database for inspection:

```bash
KEEP_TEST_DB=1 npm test
```

See [TESTING.md](docs/TESTING.md) for the manual QA checklist, curl examples and responsive/accessibility checks.
